# Demo walkthrough

A reviewer can use this sequence during a live walkthrough with the project owner. The screenshots are from the actual desktop application; they are not generated product mockups.

1. **Clone voice:** choose local processing, name the voice, read the visible script while recording, review the recording/transcript, confirm speaker permission, and create the reusable profile.
2. **Speech studio:** select that profile, enter a new sentence, generate locally, preview the take, and download the audio.
3. **Voice design:** describe a new synthetic voice, generate a sample, and reuse the resulting profile.
4. **Stories:** add dialogue blocks, assign voices, save the project, generate, and compare individual blocks with the combined output.
5. **Audiobooks:** add chapters and title/author metadata, render an M4B, and inspect the chapter markers.
6. **Transcription and dubbing:** upload a suitable clip, transcribe, review timed text, translate or edit it, assign voices, and render aligned replacement speech.
7. **Production queue:** inspect progress and completed outputs; demonstrate cancellation checkpoints and explicit retry after interruption.
8. **Models and storage:** inspect installed-model state and upstream license links; explain local processing, optional cloud routes, and workspace backups.

A live demo requires the owner's local application and installed models. The public repository does not provide a runnable application, credentials, or a hosted inference endpoint. No private recordings need to be used for a recruiter walkthrough; artificial voice references can demonstrate the workflow.
